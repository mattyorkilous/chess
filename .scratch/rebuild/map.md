# Map: Ground-up rebuild

Label: `wayfinder:map`

## Destination

A locked architecture spec for a bitboard-based, functional chess engine, plus the
standards files themselves committed and enforcing — `CODING_STANDARDS.md`,
`ruff.toml`, `ty.toml`. Done when a build session can execute the rebuild without
making further architectural decisions.

Specifying the rebuild, not performing it. Perft-vs-Stockfish and the AI speed
target are *specified* here (harness shape, measured target numbers), not built.

## Notes

- Domain: chess engine + pygame UI. Python 3.14, uv-managed, `src/chess/` layout.
- Every session: consult `/grilling` and `/domain-modeling`. Ponytail is active —
  laziest thing that holds.
- Standing preferences settled while charting:
  - **Style**: functional, immutable, comprehensions over loops. Frozen dataclasses
    carry no methods except dunders and validation; plain functions do the work.
  - **Mutation seam**: `src/chess/search/` is the *only* module permitted mutable
    state and imperative loops. TT passed explicitly, never a module global.
    Everything else — position, movegen, eval, UI — stays pure.
  - **Board**: bitboards (12 Python ints + flags in a frozen `Position`). No numpy.
  - **Moves**: packed int inside the engine, pure `encode_move`/`decode_move`,
    frozen `Move` at the UI/test boundary.
  - **Movegen**: fully legal generation (checkers + pin rays computed once), and
    **lazy** — nothing computes legal moves until asked. The old engine's eager
    `add_position_info` is the thing being fixed.
  - **Sliders**: magic bitboards, tables generated by a checked-in build script.
  - **Deps**: `pygame` + `pytest` only. Stockfish compared via raw UCI subprocess.
  - **Old code**: root `*.py` stays as a correctness oracle until perft matches
    Stockfish, then gets deleted.
- Reference: `../soccer/CODING_STANDARDS.md` is the style template.
- Module layout agreed while charting:
  ```
  src/chess/
    position.py      frozen Position, FEN parse/format
    moves.py         Move type, encode/decode
    movegen/         attacks.py (magics), generate.py
    eval.py          pure evaluation
    search/          THE mutation seam: alphabeta.py, tt.py, ordering.py
    ui/              render.py (pure), app.py (the one loop)
    perft.py
  tools/
    gen_magics.py    build-time table generation
  ```

## Not yet specified

- **Build sequencing.** Once the specs exist, the order the rebuild actually gets
  executed in, and what the cutover from the old root `*.py` looks like. Can't
  ticket until the module specs land.
- **Runtime revisit.** Whether free-threaded 3.14 (parallel perft / Lazy SMP) or
  PyPy earns its place. Blocked on measured nps — and PyPy likely loses on the
  pygame wheel constraint. Revisit after the bitboard spike.
- **Eval tuning.** If the eval grows past hand-tuned piece-square tables, there may
  be a tuning question (Texel-style, self-play). Too far out to phrase sharply.
- **Opening book / endgame tablebases.** Might be the cheapest "smarter" win of
  all, or might be a distraction. Revisit once the search spec fixes where the AI
  is actually weak.

## Out of scope

- Making our engine speak UCI itself (so other GUIs could drive it). Interesting,
  but the destination is a rebuild spec, not interoperability.
- PGN import/export, networked or online play, move database.
- A fully functional rewrite of the pygame event loop. `run_game` is a loop and
  stays one; the rest of the UI goes pure.
