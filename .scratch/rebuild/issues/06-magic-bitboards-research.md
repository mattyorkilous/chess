## Question

Magics were agreed as the slider approach, with tables generated by a checked-in
build script (`tools/gen_magics.py`) rather than computed at import. Settle the how,
from primary sources (Chess Programming Wiki, reference implementations).

- Plain magics vs **fancy** (shared, size-optimised) vs **black magic** / PEXT.
  PEXT is a hardware instruction and irrelevant to CPython — confirm that and
  discard it rather than leaving it hanging.
- The generation algorithm: trial-and-error with sparse random multipliers, and
  how long it realistically takes to find a full set.
- Whether to generate at all or lift a published constant set — and if lifting,
  the licence position.
- Table size and shape in Python terms: a `list[list[int]]`, a flat list with
  offsets, or per-square dicts. Memory and lookup cost differ, and Python's
  arbitrary-precision ints make the usual C reasoning about this wrong.
- How the mask/shift/multiply indexing survives Python having no fixed-width
  integers — the `& 0xFFFFFFFFFFFFFFFF` discipline and where it's needed.
- How the generated tables get stored: a generated `.py` module, JSON, or binary.

Findings land in a Markdown file in the repo, linked from the answer.
